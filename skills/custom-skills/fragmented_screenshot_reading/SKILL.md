# Fragmented Screenshot Reading

## Transcribe before you interpret

- List each visible message in order before you explain what it means.

- State who sent each amount and who received it when a transfer appears.

- State each person's role from the screenshot itself before you assign a motive to that person.

- Mark any name, amount, direction, or role you cannot read clearly as unread instead of filling it in.

## Separate observation from inference

- Put observed facts in one short list and inferred motives in a separate list.

- Use only observed facts to support a reply draft.

- Label an inferred motive as an inference and state the fact it rests on.

- Drop an inference when its supporting fact is missing or unclear.

## Restart after a correction

- Reread the screenshot from the literal transcription when the user corrects a direction or a role.

- Retract each inference that rested on the corrected fact in plain words.

- Rebuild the interpretation from the corrected facts instead of patching only the corrected sentence.

- Check the rebuilt interpretation for any remaining claim that still uses the old direction or role.

## Draft only from verified facts

- Base a suggested reply on facts that survive the transcription and inference checks.

- Ask the user to confirm a direction or a role when the image leaves it unclear.

- Leave out a motive claim when confirming it would require information outside the screenshot.

- Present the reply draft after the verified facts so the user can see what supports it.

## Alternatives for better results

- Ask the user for a clearer image or a short description of the sender when a key direction stays unreadable.

- Offer two reply options when two readings remain plausible instead of choosing one motive.

- Keep the draft short when the screenshot is fragmented so an unverified detail cannot hide inside a long reply.
